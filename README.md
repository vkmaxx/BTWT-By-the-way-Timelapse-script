# BTWT-By-the-way-Timelapse-script
By the way Timelapse (aka BTWT ) is script for creating smooth videos without interrupting printer moves

By The Way Timelapse is a simple G-code post-processor designed to create smoother and more stable timelapse videos of 3D prints.

BTWT analyzes an existing G-code file and automatically selects suitable moments and print-head positions for taking timelapse frames. The goal is to reduce sudden changes in the position of the print and print head between consecutive frames.

The project is designed to work with printers using Klipper and the default timelapse command:

TIMELAPSE_TAKE_FRAME
# Important before first use

Before processing your first G-code file, make sure that the camera position is configured correctly in the BTWT.ini file.

In particular, verify the following values:

camera_x =
camera_y =

They should represent the actual position of the camera relative to the printer bed.

An incorrect camera position may cause the optimizer to prefer print-head positions on the wrong side of the printed object.

The BTWT.ini file should be located in the same directory as BTWT.exe.

Supported G-code

BTWT is designed to work with G-code generated by slicers such as:

Orca Slicer
Ultimaker Cura

The program analyzes printer movements and inserts timelapse frame commands automatically.

Windows EXE version

The Windows version does not require Python to be installed.

Place the following files in the same directory:

BTWT.exe
BTWT.ini

The program is launched from the command line.

Open Command Prompt or Terminal in the directory containing BTWT.exe and run:

BTWT.exe

The program then performs the entire processing automatically according to the settings stored in BTWT.ini.

No additional command-line parameters are currently required.

BTWT automatically analyzes the G-code, selects suitable snapshot positions and inserts the required timelapse commands into the processed file.

Configuration

The main program settings are stored in:

BTWT.ini

This allows the configuration to be changed without rebuilding the EXE file.

After changing the camera position or printer configuration, it is recommended to test the generated G-code on a short print before using BTWT for a long print.
